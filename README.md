# Shader Math Cost (Mali)

Сколько стоят функции в шейдерах на GPU Mali: 120 функций, 32 GPU, OpenGL ES и Vulkan.

**Сайт:** https://maksatus.github.io/shader-math-cost/

Стоимость указана в FMA (одно умножение-сложение): «sin = 8» значит, что sin стоит как 8 обычных операций.

## ParetoGPU — профилировщик шейдеров и кадра

```
python -m paretogpu ui
```

Или двойной клик по `start.bat`: сначала проверяет, что установлены Python 3.10+, malioc, RenderDoc и Unity (`python -m paretogpu.doctor`) и пишет, чего не хватает и где это взять (сам ничего не ставит), затем запускает интерфейс. Аргументы передаются в `ui` (например `start.bat --port 8800`). Когда закрыто последнее окно, сервер останавливается сам (если идёт проверка — после её окончания) и консоль закрывается; `--stay` оставляет его работать.

Открывает окно (Edge в режиме приложения) на `http://127.0.0.1:8765` с вкладками: «Проверка кадра» (проект из Unity Hub, три настройки и одна кнопка: снимок кадра из открытого редактора, его цена на Mali с прогрессом и оценкой оставшегося времени, в конце самые дорогие шейдеры), «Отчёты» (проверенные кадры из `paretogpu/out`, пересчёт), «Сравнение» и таблица цен функций (этот сайт).

Каждый расчёт снимка сохраняется в `<снимок>/costs/`. «Сравнение» показывает разницу двух расчётов по кадру, стадиям, шейдерам, вариантам и событиям и делит её на цену шейдеров, объём работы (пиксели, вершины) и состав вариантов. Поправили шейдер — «Отчёты» → «Пересчитать»: тот же кадр с новыми ценами, разница только от шейдеров. То же из консоли: `python -m paretogpu compare <A> <B>` → `compare.html`. Экспорт шейдеров, замер папки и `report.csv` есть только в консоли (`python -m paretogpu -h`). Отчёты открываются только локально и в git не попадают.

## Обновить данные

Нужны Python 3 и [Arm Performance Studio](https://developer.arm.com/Tools%20and%20Software/Arm%20Performance%20Studio) (malioc).

```
python -m paretogpu bench
```

Функции задаются в `paretogpu/model/functions.py`. Только пересобрать `data.js` и сводки из готового CSV: `python -m paretogpu bench --site-only`.

## Аппроксимации

Быстрые замены функций (кнопка «≈ быстрее» в таблице) лежат в `docs/approx.js`. Пересобрать: нужны numpy, scipy и malioc, PySR только для поиска формы формулы (`bench/approx/pysr_*.py`).

```
cd bench/approx
python build_approx.py
```

Формулы, диапазоны и результаты замеров на устройствах задаются в `bench/approx/build_approx.py`.

## Как устроен код ParetoGPU

```
paretogpu/
  model/      типы данных и константы: VariantKey, событие кадра, замер malioc, цена кадра (без ввода-вывода)
  core/       чистые расчёты: цена шейдера и кадра, сравнение, динамические циклы, абляция, материалы
  adapters/   внешние инструменты: malioc, Unity (CLI, компиляция вариантов, снимок кадра, .mat), RenderDoc
  store/      файлы результатов: paretogpu/out, папка вариантов проекта, архив расчётов
  views/      HTML-шаблоны, CSV, Reporter (лог и прогресс для интерфейса)
  app/        общие сценарии: движок артефактов (компиляция → замер → циклы), материалы, абляция
  features/   команды: у каждой аргументы, сценарий, фазы и отчёт в одном описании
  cli.py, ui/ входы: командная строка и локальный интерфейс, оба строятся из описаний команд
```

Импорты идут только сверху вниз: `cli, ui → features → app → adapters | store | views → core → model`, а `adapters`, `store` и `views` друг друга не импортируют. Это проверяет `tests/test_layers.py`.

Новая команда — модуль в `features/` с `Command(...)` и строка в `features/__init__.py`: командная строка и формы интерфейса появятся сами.

Тесты: `python -m unittest discover tests` (там же проверка слоёв и статическая проверка модулей; на GitHub их запускает `.github/workflows/tests.yml`).

Регрессия на своих данных: `python tools/regression.py baseline` до изменения и `python tools/regression.py check` после. Сверка берёт два последних снимка проекта из `paretogpu/out`, копирует их и папку вариантов в `paretogpu/out/_regression` (сами снимки не трогает), прогоняет все команды без Unity и сравнивает результаты, вывод и ответы интерфейса.
