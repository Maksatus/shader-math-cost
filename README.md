# Shader Math Cost (Mali)

Сколько стоят математические функции и текстурные выборки в шейдерах на GPU Mali. Цифры получены статическим анализом Mali Offline Compiler (malioc) для всех доступных GPU, OpenGL ES и Vulkan.

**Сайт:** https://maksatus.github.io/shader-math-cost/

Главная таблица показывает стоимость каждой функции в FMA (одно умножение-сложение) и медианы по поколениям GPU. Клик по функции открывает раскладку по всем 32 GPU.

## Что измерено

- 32 GPU Mali: 5th Gen, Valhall и Bifrost через malioc 2026.5, Midgard через malioc 8.4 (новый его не поддерживает)
- OpenGL ES и Vulkan
- типы float, half (mediump), float4, half4; целые числа — только 32-битные
- 120 функций: арифметика, округление, степени и логарифмы (включая `pow` с константой), тригонометрия, гиперболические, производные, векторные, сравнения, конвертации, целые числа, матрицы, хелперы Unity URP, текстурные выборки

## Файлы

- `docs/` — сайт (GitHub Pages раздаёт эту папку)
  - `index.html` — страница
  - `data.js` — данные для страницы (тот же CSV, упакованный, чтобы страница открывалась и с диска)
  - `mali_math_cost.csv` — все измерения: одна строка = API × GPU × тип × функция
  - `summary_gles.csv`, `summary_vulkan.csv` — сводка: медиана по архитектурам
- `bench/` — генератор шейдеров (`shadergen.py`), список функций (`functions.py`), раннер (`run.py`), сборка данных для сайта (`build_site.py`)

## Обновление данных

Нужны Python 3 и [Arm Performance Studio](https://developer.arm.com/Tools%20and%20Software/Arm%20Performance%20Studio) (в нём malioc). Пути к malioc заданы в начале `bench/run.py`.

```
python bench/run.py            # все GPU, по потоку на ядро; повторный запуск берёт готовое из кеша bench/.cache
python bench/build_site.py     # пересобрать docs/data.js и docs/summary_*.csv
```

`--gpus Mali-G57,Mali-G52` — только выбранные GPU; `--no-legacy` — без Midgard. Новые функции добавляются в `bench/functions.py`. После коммита и пуша в `main` сайт обновится сам.

## Методика

- Каждая функция компилируется как цепочка из N зависимых вызовов `x = f(x, a) + w` во фрагментном шейдере. Операнды берутся из varying: цепочки на uniform компилятор сворачивает.
- Стоимость одного вызова = (такты(N=24) − такты(N=8)) / 16 минус то же самое для цепочки без `f`. Так убирается фиксированный оверхед шейдера. Если шейдер вытесняет регистры в стек, берутся цепочки 8→16 или 4→8 (колонка `chain`).
- Стоимость берётся по самому загруженному арифметическому блоку: FMA / CVT / SFU на Valhall и 5th Gen, общий ALU на Bifrost и Midgard.
- `× FMA` — стоимость в единицах скалярной highp FMA на том же GPU и API.
- Текстуры: время текстурного блока относительно обычной `tex2D` на том же GPU, плюс отдельно арифметика на подготовку координат (`alu_fma`). malioc предполагает билинейную фильтрацию 32-битной текстуры.
- Дорогая часть функции должна зависеть от `x`, иначе компилятор переиспользует её между шагами цепочки. Поэтому деление меряется как `a / x`, `smoothstep(a, x, b)`, `mod(a, x)` и т.д.
- Стоимость маргинальная: `mul` или `pow(x, 2)` перед сложением сливаются в FMA и стоят ≈0; `abs`, `saturate`, `f16tof32` — модификаторы операндов, обычно бесплатны.
- Это статическая оценка компилятора, а не замер на устройстве. Она хороша для сравнения функций между собой и даёт порядок величин.
